# Claude 托管会话恢复与隔离

更新：2026-10-08。实现记录 CC-20261008-008；基线 release `b4430850844263e3fd3d2d180f514099bffad04e`，上游 `3f1a2ea0`。

## 行为与约束

默认仍为严格模式：同一个 session UUID 固定账号，账号不可用就返回错误。
托管恢复按分组明确启用，需要新建客户端会话。原有严格会话不能静默迁入托管模式。

托管模式区分两层 ID：

- 客户端逻辑对话 L：CLI 继续使用自己的 ID。
- 上游会话 U：网关生成独立 UUID，每个 U 永远绑定同一个账号。

数据库以 `(认证用户 ID, 分组 ID, 客户端 session UUID)` 唯一定位对话。不同用户、分组和 session
各有独立的记录、密文、上游 UUID、处理权和恢复快照。相同正文不用于判断是否同一会话。
上游 UUID 不作为普通客户端 session 接受，关闭功能后也不能把旧托管会话偷偷交给严格调度重新分配。

输入中的 metadata 与会话头先检查一致性，再修改出站身份。出站头、metadata、实际凭证和当前会话段
再次检查。不同 session 的摘要不能互相解密；缓存或数据库错误不会授权跨会话发送。
JSON 重复键、来源不一致的助手回复、外来 thinking 签名、历史回退和不能确认的分叉都会阻止恢复。

## 配置

默认关闭，示例中的凭证必须由部署者提供。所有实例必须使用同一份配置和加密密钥。

```yaml
gateway:
  claude_recovery:
    enabled: true
    group_ids: [7]                    # 仅指定的 Anthropic 分组
    encryption_key: "<BASE64_32_BYTE_KEY>"
    summary_url: "https://api.anthropic.com/v1/messages"
    summary_api_key: "<SUMMARY_SERVICE_KEY>"
    summary_model: "claude-haiku-4-5-20251001"
    max_history_bytes: 8388608
    max_summary_input_bytes: 262144
    max_summary_tokens: 4096
    checkpoint_every_turns: 3
    max_summary_calls_per_user_day: 20
    context_window_tokens: 200000
    retention_hours: 168
    lease_seconds: 120
    summary_timeout_seconds: 45
```

生成密钥：`openssl rand -base64 32`。不要使用示例占位符，也不要提交真实密钥。
以上字段也支持既有配置加载器的环境变量，例如 `GATEWAY_CLAUDE_RECOVERY_ENABLED`、
`GATEWAY_CLAUDE_RECOVERY_ENCRYPTION_KEY`。分组数组优先通过配置文件提供，避免不同部署环境的数组解析差异。

摘要端点必须兼容 Anthropic Messages 的请求与响应格式，并使用 HTTPS；摘要客户端不跟随重定向。
可以使用自己的 Sub2API 摘要专用分组，但该分组必须关闭托管恢复，否则会被递归保护拒绝。
摘要调用携带 `X-Sub2API-Recovery-Purpose: checkpoint`；它没有跳过会话校验的权限。

摘要费用由配置的摘要服务凭证承担。主请求继续按原网关规则计费；摘要调用次数及报告的输入 / 输出
用量单独记录在 `claude_recovery_summary_budget`，不伪装为主模型用量。未知摘要调用结果单独计数，
不当作已确认零消耗。日调用次数按 UTC 日期限制，失败尝试也占次数。

## 正常请求与检查点

鉴权、模型权限、内容审核和计费预检通过后，才进入恢复准备；进入流式响应后不再偷偷换号。
生成请求获得数据库处理权并定期续期；其他并发生成请求得到冲突响应，不能同时修改同一对话。
计数请求使用当前会话段和相同转换规则，不主动发起迁移。迁移后的模型发送前还会使用同一账号、
同一上游 session 对实际恢复正文进行 token 计数，超过配置预算就停止，尚不发送模型请求。

只有完整成功的响应才加入已确认历史。服务端记录实际回复的内容；下一轮提供的历史必须与之前
已确认的输入及回复匹配。缓存标记等已知表示差异可以规范化；工具输入中名为 cache_control 的业务字段
不会被误删。Opaque thinking 块如被提供，必须与本对话已记录的块一致。

后台工作器从 PostgreSQL 领取待处理检查点：首次生成一份，之后按完整回合数更新，进程重启后可继续领取。
增量摘要使用已有摘要和新增材料，所有事实引用需要与原始材料逐字匹配；这验证引用来源，不代表
模型给出的解释永远正确。用户文字指令单独保留原文，最近观察结果原样引用，不能静默截断关键材料。

内联图片 / 文件保留原始协议块，不要求文本摘要模型猜测图像内容。远程 URL、账号文件 ID 或无法取得
字节的附件不自动迁移。对话内容、检查点和重放响应使用 AES-256-GCM 加密；认证附加数据包含用户、分组、
客户端会话、记录 ID 和数据用途，恢复快照还绑定具体上游 UUID。

## 迁移与停止条件

仅当原账号已删除、状态明确为 disabled，或 active 账号被关闭调度，且位于一个新的普通用户回合，
才允许自动迁移。新账号必须仍在原分组、支持相同已验证模型、未启用改变会话 ID 的旧身份策略。
权限拒绝后的对话不自动迁移。模型映射到另一个模型也不允许静默继续。

迁移在数据库中检查处理权和当前版本，创建新 U、登记新账号及固定恢复快照，再原子切换当前指向。
旧 U 和原账号的绑定一直保留。开始实际模型发送前，再把操作从 prepared 原子改为 sent；同一操作
不能发送第二次。不存在持有数据库事务等待模型响应的做法。

| 情况 | 行为 |
|---|---|
| 明确未发送的本地失败 | 释放处理权，允许后续重试 |
| 400 / 401 / 403 / 404 / 413 / 422 / 429 / 529 明确拒绝 | 保留账号；403 同时阻止自动迁移 |
| 500 / 502 / 503、发送后断连或结果不明 | 进入 uncertain，停止自动重放 |
| 已输出部分 SSE、缺少终止事件 | 保留不确定状态，不拼接另一账号的回答 |
| 工具调用尚未获得匹配结果 | 不迁移，不把工具调用搬到另一账号重发 |
| 不同 session / 用户 / 分组的记录、签名或密文 | 本地拒绝 |
| 摘要预算不足、材料过期、无法对齐历史、计数失败 | 本地失败，不猜测上下文、不更换更多账号 |

迁移后的前缀固定，不会被后来的后台摘要改写。CLI 后续仍发送完整旧历史时，网关先核对已覆盖的
消息边界，再用该固定快照替换旧前缀，接上当前会话段的新历史。旧的 previous-message diagnostics
在托管模式下省略；thinking 签名不重算、不伪造。生成的新首段文字按已验证的 UTF-16 算法重算归因后缀，
cch 仍在最终正文上计算。

## 幂等、恢复和边界

- 支持显式 `Idempotency-Key`（数据库只保存其哈希）：同一作用域、同一键和同一请求才能重放已完成结果；相同键但正文不同会拒绝。
- 明确未执行或被拒绝的尝试可再次申请，原失败尝试保留；已发送且结果未知的操作不会因处理权过期而重发。
- 没有可靠幂等键时，不把相同正文猜成同一次请求。未经修改的客户端无法提供强于其确认机制的“恰好一次”交付保障。
- 活跃段的账号凭证身份改变会停止续用；普通 OAuth token 刷新在账号身份不变时可以继续。
- 非流式响应在持久化结果后返回；流式响应保持实时输出，持久化失败可能使后续请求暂停，已经发出的字节不能撤回。
- 单次捕获用于核对 / 重放的响应上限为 2 MiB，超出时停止自动恢复；不会假装保存了完整回复。
- 自动恢复不能保证摘要无损，也不能保证新模型永远不再提出相似工具操作；外部工具的幂等仍由执行端负责。

当前支持固定模型 `claude-sonnet-4-6`、`claude-opus-4-6`、`claude-haiku-4-5-20251001`，以及 CLI 2.1.292。
Messages、Chat Completions、Responses 各自可使用托管会话；同一逻辑对话不跨协议格式 / 模型切换。
Responses 必须提供完整 input，不接受无法还原的 previous_response_id。多候选回答、未验证版本、
子代理 / 远程会话、辅助生成、历史编辑与不能匹配的 /compact 或 /resume 路径会停止自动恢复。
严格模式保留既有行为，不受这些托管模式的支持范围限制。

## 部署、保留和回滚

新增迁移 `243_claude_managed_recovery.sql`；既有 `242_claude_session_ownership.sql` 继续承担不可改绑的上游归属。
历史材料到期会清除密文，归属及操作墓碑保留，避免过期后重发或换号。清理由服务工作器运行，关闭自动恢复也继续清理到期材料；后台摘要仅在明确启用时运行。
加密密钥需要和业务库一起备份；更换密钥而未迁移密文会使历史无法恢复。

先统一部署全部实例，再为选定分组启用，并新建客户端会话。关闭开关后，旧托管对话返回错误，不降级为另一种路由。
回滚旧二进制之前必须先阻断托管入口并让客户端开启新会话；旧代码没有托管注册表和历史重建能力。
不要删除绑定表、清空恢复记录后复用旧客户端 ID，或混用不同配置 / 加密密钥的实例。
