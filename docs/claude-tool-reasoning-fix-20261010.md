## 修复行为

- **并行限制：** Chat / Responses 的 `parallel_tool_calls` 映射到原生
  `tool_choice.disable_parallel_tool_use`，同时保留 auto、required 和指定工具名称。
  没有指定 tool_choice 时补 auto；none 已禁止一切工具调用，保留其原生形状；没有工具时
  不凭空添加 tool_choice。未知选择类型与显式并行控制组合时明确报错。
- **工具 strict：** 原生工具结构和转换器保留 strict。strict=true 的 schema 原样保留，
  不再经过会摊平联合的旧兼容处理；缺少 object 根类型或不支持 strict 的 server tool
  明确返回错误。nil / false 保留既有非严格 schema 兼容策略。
- **结构化能力：** 第一方普通转换请求的 strict=true 和输出 JSON Schema 共用结构化
  能力声明；禁用 beta 或有效头覆写丢弃必要能力时返回 400。原生保留、自定义 origin 和
  OAuth 不适用 API Key 头覆写等既有边界继续生效；不声称提供方已接受或授权该能力。
- **预算：** Sonnet / Opus 4.6 的显式非 low 推理使用已测 adaptive；手动预算按最终输出
  上限约束，必须至少 1,024 且小于 max_tokens，不能再把 high 固定为超过上限的 10,240。
  旧手动预算的 effort 档位映射保留，较大上限下不声称与 CLI 缺省预算逐字节等价。
- **none：** 旧模型明确发送 disabled，移除由 none 错误生成的预算，不输出 effort=none。
  Schema 保留。5.5 的 between_tools / 不支持 none 的既有处理不变。
- **冲突：** 不支持的 effort 和“强制工具选择 + 启用推理”明确返回 400，不能偷偷改变
  调用方的工具选择或启用未知推理档位。

## 504 组合同与新增拒绝边界

原 504 组输入、六模型、两账号、三入口和 14 个控制完整保留。它们已成为永久
`TestClaudeToolConstraintContract`；不再仅依靠观察进程退出 0。

原来的 44 个明确拒绝继续存在。另外八个 Haiku 4.5 请求（high + 64 / 1,024 上限 × 两账号 ×
Chat / Responses）现在明确返回 400，因为无法同时保留最低 1,024 思考预算和更小输出上限。
这是一项新增的输入拒绝策略：**分母仍是 504，52 个明确拒绝，452 个成功请求**。没有删除
原失败输入，也没有用关闭思考或提高 token 上限掩盖冲突。原生 CLI 在这些低上限上的自身
预算边界保留在 002，原生转发不受本转换策略改写。

独立判定器增加 true 并行开关、strict 能力头、精确的 none 类型、adaptive 及预算下限检查；
修复前观察仍失败，修复后的 504 组检查通过。额外单测覆盖 nil / true / false、none / 指定工具、
严格 Schema 的联合与大整数、非法 Schema、1 至 128,000 的上限、未知 effort 及策略禁用。
既有 Schema / stop / token / Unicode 摘要合同继续独立运行。
