使用固定的 Linux x64 CLI 2.1.292 / 2.1.295，SDK 0.128.0 / runtime v26.3.0。
执行前由既有运行器校验官方二进制 SHA-256、断网接口 / 路由及回环域名解析。
新增 `sse_structure_lab.py` 复用 014 的 11 场景，再增加 21 种结构 / 顺序 / 工具输入。
全部响应和凭据都是合成数据，没有访问真实模型提供方。

除 SDK 解帧代码外，本轮检查 CLI 应用层组装逻辑：它按块索引保存内容，拒绝对已关闭块
追加增量，校验增量与块类型，并在没有终止信号时触发应用层恢复。源码锚点包括
`content_block_delta_without_delta`、`content_block_closed_delta`、
`content_block_type_mismatch_thinking_delta` 和重复开始判定。

is_error、完整结果、用量、请求 stream 序列、响应数量及首份响应正文。

关键边界如下：

| 输入 | 两版原生 CLI 的结果 |
|---|---|
| 已知事件的 data 为 null | 失败并转入非流式回退 |
| 已知事件的 data 为数组、数字或无 type 的空对象 | 忽略该值，保留后续正常正文 |
| message / content_block / delta 为 null | 失败 |
| 缺 message_start、空流、只有 message_start | 失败 |
| 块已关闭，但 message_delta / message_stop 都缺失 | 四次流式请求后失败，不能认为干净 EOF 就是完成 |
| 块已关闭后再追加 delta | 四次流式请求后失败 |
| text 块收到 thinking_delta | 失败 |
| 相同 message_start 在内容开始前重复 | 成功，正文及单次用量保持正确 |
| 相同空 content_block_start 在首次增量前重复 | 成功，不生成两份内容 |
| 完整但没有内容块的消息 | 两条流式请求后成功，结果为空 |
| 有效或截断的工具参数 | 两条流式请求后成功，下一轮历史的处理方式不同 |

仍保留 014 的成功负对照：单独缺 message_stop 或 message_delta 的已测场景成功，
所以不能把所有缺失终止事件的输入一律拒绝。两者都缺失的 closed-content 是本轮新增
失败，纠正 014 对这种输入检查不足的问题。

非流式回退仍由模拟器明确返回 400 `LOCAL_NONSTREAM_FALLBACK_NOT_PROVIDED`。
四次流式重试、空完整消息的两次请求、工具续轮，都是原生应用层行为；网关不据此增加
隐藏请求。比较对象是单份响应的接受 / 拒绝及转换内容，不宣称整个应用流程完全相同。

## 工具参数边界

工具场景的 Read 在该实验会话中被禁用，返回的是工具不可用错误，没有成功读取文件。
模拟器在下一条流式请求返回固定文本，以观察 CLI 如何保留工具历史。

有效参数的下一轮 input 为普通对象；截断的 `{"file_path":` 在 CLI 历史中变成
`{"__unparsedToolInput":{"raw":"{\"file_path\":","len":13}}}`。网关的 OpenAI 函数调用
协议继续完整保留原始 arguments 字符串，包括截断内容，不把它修补成可执行参数。
该标记是 CLI 应用层的恢复表示，网关没有新增工具执行或自动历史修复；API 调用方仍须
处理无法解析的工具参数。此边界在固定测试中单列，不能把字符串保真称为完整工具恢复等价。

## 生产修复与固定断言

在修改生产实现前，32 输入 × 四个处理器的 128 个组合中有 46 个失败。新样本从原生
模拟器的首份响应生成并固定 SHA-256，成功 / 失败预期来自上述独立 CLI 结果。
API 参数字符串与 CLI 后续工具历史采用各自的明确合同，没有用网关结果生成预期。

共享读取器现在：

- 拒绝 null 事件及缺失的消息 / 内容 / 增量结构；忽略没有已知 type 的非 null JSON 值。
- 跟踪消息是否开始、块是否打开、块类型与是否已有增量，拒绝开始前或关闭后的操作、
  类型错配及缺终止信号的 EOF，包括空流和只有开始事件。
- 将首次增量前完全相同的块开始事件去重，避免下游重复项目；内容已改变后的重新开始、
  不同内容的重新开始或消息在已有内容后重启，仍明确拒绝。转换器无法撤回已经发出的
  OpenAI 增量，这些限制是网关策略，不列为原生对任意重启输入的完全等价。
- 保留空完整消息、单独缺一个终止事件的已测成功行为、有效及截断工具参数原始字符串。

源码补充断言验证 `typeof delta.type === "string"` 的边界：空字符串和未知字符串可
忽略，缺失 / null / 数字失败。该组五个向量是源码导出的本地断言，不计入 64 个 CLI 场景。

新增固定 fixture `claude_sse_structure_contract.json`；旧 142 份证据文件不变，总数为
143。CI 必需测试增加结构矩阵和声明类型检查，总数为 35。可设置
`CLAUDE_SSE_STRUCTURE_CAPTURE_ROOT` 将任一版实际捕获的首份响应重放到四个生产处理器。
