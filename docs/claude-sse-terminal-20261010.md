SDK 0.128.0 / runtime v26.3.0。分发源码中的 `fromSSEResponse` 按 SSE 的 event 名

ping 和未知事件忽略。来源是 292 的 `chunk-9yn9h839.js`、295 的 `chunk-75cm4bmg.js`，
模块哈希与 [013 报告](claude-sse-framing-20261010.md)一致。

新增 `sse_terminal_lab.py`，两版未修改 CLI 各运行以下 11 场景。全部使用 network-none
容器、回环 TLS、假凭据和合成响应，未挂载宿主登录配置。每个初始响应均为 HTTP 200 SSE。

| 场景 | 两版 CLI 的实际结果 |
|---|---|
| 完整流 | 成功，正文准确，输入 / 输出 token 为 17 / 9 |
| 只有 message_stop 缺失 | 成功，正文及 17 / 9 用量保留 |
| 只有 message_delta 缺失 | 成功，正文保留，输出用量保持已收到的 0 |
| 未知 event，正文伪装成合法 text_delta | 忽略该事件，正文没有额外文本 |
| 未知 event，正文不是合法 JSON | 忽略该事件，正常完成 |
| message_start 前的 error | 初始流失败，CLI 发起非流式回退 |
| 部分文本后的 error | 初始流失败，CLI 发起非流式回退 |
| 已知事件中的非法 JSON | 初始流失败，CLI 发起非流式回退 |
| 内容块未结束且无终止信号的 EOF | 初始流失败，CLI 发起非流式回退 |
| 负内容块索引 | 初始流失败，CLI 发起非流式回退 |
| content_block_start 前的 delta | 初始流失败，CLI 发起非流式回退 |

每个成功场景只有一次 `stream:true` 请求。每个失败场景是一次 `stream:true`，随后一次
`stream:false`，即使配置 `CLAUDE_CODE_MAX_RETRIES=0` 也有这次应用层回退。模拟器对
非流式回退明确返回 400 `LOCAL_NONSTREAM_FALLBACK_NOT_PROVIDED`，所以 CLI 最终退出 1，
没有超时。这个最终 400 是实验设计，不能归因于提供方，不能将其描述为原始 SSE 错误状态。
此处验证流失败与回退触发，不声称完整复刻 CLI 应用层回退策略。

固定判定器 `verify_sse_terminal.py` 检查完整 11 场景集合、退出状态、is_error、
请求的 stream 序列、成功正文及用量。两版共 22 场景 / 34 条模型请求通过。
每个场景的一份 SSE 响应经 PCAP 独立核对，共 22 份正文哈希一致、内核丢包 0。

## 网关差异与修复

首次固定四路径回归共 44 组，原实现失败 26 组，其中负索引在两个缓冲处理器触发 panic。
上轮 013 处理了解帧与底层读取错误，没有覆盖这里的事件语义；其既有通过范围保持有效。

新增共享 `ScanEvent` 层，供 Chat / Responses 的流式和缓冲处理器共同使用：

- 六种 Messages 核心事件先按 event 名分派；未知事件和 ping 在 JSON 解码之前忽略，
  不能靠正文 type 将未知事件变成文本增量。
- `event:error` 保留为已有类型化 SSE 错误；已知消息事件 JSON 损坏则立即失败。
  上游完整错误 envelope 的 message 沿用既有脱敏函数，并通过 JSON 编码输出；
  解析错误 / 读取错误使用固定文本，不反射 JSON 碎片或底层网络地址。
- 校验内容块索引，阻止负值、未开始的块和不连续 start 索引造成 panic、丢弃或错配。
  未观察到的异常序列不列为已证明原生等价。
- 没有终止信号且内容块仍打开时，EOF 返回错误；已收到 stop_reason 或 message_stop
  的旧兼容收尾保留，不因本轮结果直接强制所有上游都必须发送两个终止事件。
- 缓冲失败返回 502，流式失败输出既有 OpenAI server_error 形状并结束，不生成成功收尾
  或 `[DONE]`；流式保留已知用量。HTTP 200 内的错误不凭 error.type 猜测真实 HTTP 状态。

网关保持原有“调用方拥有重试”职责，不在转换器内增加非流式回退或换号请求。本文比较
每份响应的接受 / 拒绝、正文和用量；不能把网关一次转换与 CLI 两次应用层请求称为完全
相同的流程。原生 Messages 透传及通用 apicompat 的其他消费者未改动。
